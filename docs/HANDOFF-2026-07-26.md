## 3. The single most important thing to know

**The skip-return convention is inverted from what a C programmer expects.**

| callee does | returns to | the 1973 header calls it |
|---|---|---|
| `MIN LREG,B` then exit | **`L+1`** | `%RETURN` — the **success** path |
| falls through | **`L+0`** | `%FAILURE RETURN` |

So **the word immediately after a `JPL` is the error handler.** This is proven
three ways: the `SRET` macro (`/mnt/e/Dev/Ronny/TSS/src/TSS2.SYMB:291`), the
`SUIB` usage (`.../src/TSS5.SYMB:219` vs its header at `:186`), and the
`CRFIL` call site (`.../src/TSS5.SYMB:263`).

Two idioms follow and are everywhere:

```
    JPL I (RBLOC
    JMP *-1          /* on failure, RETRY forever          */

    JPL I (IUSER
    JPL I (FTLER     /* on failure, unrecoverable halt     */
```

I got this backwards initially and it corrupted several conclusions. Full
explanation at the top of `/mnt/e/Dev/Ronny/TSS/docs/TSS-PSEUDOCODE.md`.

## 4. Findings, with evidence

All cite absolute paths. Anything not directly read is labelled.

### Verified from source and confirmed by running

**`LOGON` has a master password: `..` (two periods).**
`/mnt/e/Dev/Ronny/TSS/src/TSS4.SYMB:568` — `SUB (636; JAZ L6A` bypasses the
password comparison entirely. Passwords are a 16-bit rolling hash,
`passw = (passw << 3) + c` (`:566`); `0636` octal = 414 = `(46<<3)+46` where 46
is ASCII `.`. Present in Lewendal's 1973 original *and* in
`/mnt/e/Dev/Ronny/TSS/reference/LIST4.SYMB:1153`, the 1978 assembly listing.
The literal `636` occurs exactly once in the whole corpus.

Verified by running: user `SECURE`, real password `123` —
`999` REJECTED, `123` ACCEPTED, `..` ACCEPTED. Full write-up in
`/mnt/e/Dev/Ronny/TSS/docs/PROJECT-DESCRIPTION.md` §9.
Reproduce with
`/tmp/claude-1000/-mnt-e-Dev-Ronny-TSS/7c2e2e2d-9fba-47b5-9f3b-21e3b9245046/scratchpad/securepw.py`
(scratchpad — copy it somewhere permanent if you want to keep it).

**The disc-space "track leak" does not exist.** `DISK-SPACE` maps to `DKSP`
(`/mnt/e/Dev/Ronny/TSS/src/TSS4.SYMB:1300`), which population-counts the MIB
bitmap — a **global** free-track total. `LIST-TRACKS` maps to `LTRKS`
(`.../src/TSS5.SYMB:1600`) and is the **per-user quota**. Two different
numbers. `CRUSE` legitimately spends one track per user for the UIB
(`.../src/TSS5.SYMB:97`), so `15 -> 14 -> 13` was correct behaviour.

**`BACKUP` is a no-op on NORD-10.** `/mnt/e/Dev/Ronny/TSS/src/TSS5.SYMB:747` is
`"N10 / JMP BSSS` — the implementation exists only in the `"NN10` branch.

**`DEVER` patches one word of disc page 0**
(`/mnt/e/Dev/Ronny/TSS/src/TSS5.SYMB:594`), which is *why* `DKRST` begins
`JMP *+2; CORLD` (`.../src/TDUMP.SYMB:269`) — the coreload address is a runtime
parameter read from `core[1]`, so `DEFINE-VERSION` can switch coreloads without
reassembly.

**`LOAD-SYSTEM` needs no front panel.** `LOADV`
(`/mnt/e/Dev/Ronny/TSS/src/TSS5.SYMB:621`) reads disc page 0 into core 0 then
does `RCLR DP`, zeroing the PC so execution continues at what it just loaded.

**Overlay calls route through core location 0.** `GOVER` emits a 6-word stub in
`BLUES` that does `SAX 0; SWAP DP SX` (`.../src/TSS3.SYMB:19`); page zero has
one-word trampolines at 0/1/2 → `GOVX`/`USTK`/`STK`
(`.../src/TSS1.SYMB:62-71`). Stack frames record the current overlay and `USTK`
reloads it on return (`.../src/TSS2.SYMB:330`).

**224 users x 56 files.** 7 user-table blocks x 32 slots; `RUTBL`'s header says
`%T = INDEX (FROM 1 TO 7)` (`.../src/TSS2.SYMB:3034`). Confirmed independently
by MINIT's `REGENERATE` bounds (`.../src/MINIT.SYMB:212`, `0340` = 224).

**`RTRK` documents a failure it cannot produce** — header at
`.../src/TSS2.SYMB:2691` vs the code at `:2708`.

**The swapper contains its own pseudocode.** `/mnt/e/Dev/Ronny/TSS/src/TSS1.SYMB:2927-3040`
carries the algorithm in `%` comments in a PLANC-like notation. 25 comment
lines have `:=`, 42 have `IF`/`FOR`/`GOTO`.

### Defects found 2026-07-26

All four written up in `/mnt/e/Dev/Ronny/TSS/docs/TSS-COMMAND-VALIDATION.md`
PART IV.

- **D1. `CREATE-USER` succeeds but prints `ALREADY EXISTS`.** `CRUSR`
  (`.../src/TSS4.SYMB:952`) routes **every** `CRUSE` failure code to one
  message. Cause confirmed: the failing step is the track-quota charge, which
  happens *after* the account is fully created.
- **D2. `LOGOUT` leaves the terminal dead** — never reprints `@ENTER`.
  Reproduced twice. Use a fresh boot per session instead.
- **D3. Nobody has a track quota after bring-up, including `SYSTEM`.**
  `TRANSFER` with `TO USER` = `FROM USER` mints quota from nothing
  (`.../src/TSS5.SYMB:1589` skips the debit leg) — verified 0 -> 20 with the
  global free count unchanged. This is the required bring-up step, and it means
  quota is fully decoupled from physical free space.
- **D4. The file-create path exists but the command processor rejects it.**
  A leading `"` on the name is the create marker (`.../src/TSS3.SYMB:1350`);
  `OPEN-FILE "MYFILE,W` returns `BAD FILENAME`. Reachable from a program via
  `MON 34`, not from the terminal.

## 5. Open questions, in priority order

**1. Why the swapper appeared to find no free page. ANSWERED 2026-07-27 —
an assembler code-generation bug, now fixed.**

Measurement at the hang gave `IDXA = IDXB = -1` with `J = 36` and 35 of 36
frames free. The reading was correct and the addresses were correct; the
conclusion that it "cannot arise from this code" was wrong because the
*emitted code did not match the source*.

`mac_stmt.c` chose the displacement base from the mode bits and treated the
X bit alone as meaning X-relative. That is true only of mode 4 `(X)+D`.
Mode 6 `,I ,X` is `((P)+D)+(X)` — ND-60.096.01's addressing-mode table names
it **indirect P-relative indexed**: `D` locates the indirect pointer word
relative to `P`, and `X` is added after that word is fetched. With the X
location counter at 0 the subtraction was a no-op, so the symbol's absolute
low byte survived into the displacement field.

Only **backward** references were affected. A forward reference emits a bare
opcode and is patched by `MAC_FIX_PREL8`, which is P-relative and correct.
This is why the bug survived so long, and why the earlier minimal repro
appeared to exonerate `mac-c` — that repro used a forward reference.

Nine sites were miscompiled, all in TSS1's swapper, because its locals block
sits between `SW4` (forward, correct) and `SW5` (backward, broken). At
`006732` `LDA I J2,X` assembled to `047324`, displacement `-44`, addressing
`006656` — a word of the `AAA -2` instruction — instead of `PDTBL[J]`. Every
iteration read the same fixed word, so the scan never saw a free frame,
`IDXA` and `IDXB` stayed `-1`, and `SW6` fell into `FTLER`. That accounts for
all four measured values including `J = 36`.

Fixed in `/mnt/e/Dev/Ronny/TSS/mac-c/src/mac_stmt.c`; pinned by test [17] in
`/mnt/e/Dev/Ronny/TSS/mac-c/tests/test_mac.c`. Verified on a running machine:
`MEMORY 40000 44000` now returns to the `@` prompt with `IDXA = 2`, `J = 2`.
The golden dumps are unchanged (679/693 A, 675/689 B) — this class of bug
alters only the displacement byte, never the word count, so the symbol-address
oracle is blind to it by construction.

**2. Which `CRUSE` failure fires on `CREATE-USER`. ANSWERED 2026-07-26.**
`SYSTEM`'s quota is **0** after bring-up, so the final `UTRK(+1, user 1)`
(`.../src/TSS5.SYMB:106`) is refused and `CRUSE` takes its failure return. See
`/mnt/e/Dev/Ronny/TSS/docs/TSS-COMMAND-VALIDATION.md` D1 and D3.

**3. Can a freshly created user create a file? ANSWERED 2026-07-26 — no.**
`OPEN-FILE "HISFILE",W` as a zero-quota user returns `NO MORE TRACKS
AVAILABLE`; the same command as a user with quota returns `FILE NUMBER = 100`.
See `/mnt/e/Dev/Ronny/TSS/docs/TSS-COMMAND-VALIDATION.md` D5.

**3b. Why `OPEN-FILE "NAME,W` is rejected. ANSWERED — bad syntax, not a bug.**
The `"` is a **delimiter pair**. `OPEN-FILE "NAME",W` works. An unterminated
quote reaches `O16` (`.../src/TSS3.SYMB:1376`) with `NEWF < 0` and exits via
`OF8` = `BAD FILENAME`. This resolves the long-standing "no way to create a
file" note in the user manual. See D4.

**4. Where SYSTEM's initial quota comes from. ANSWERED:** nowhere. `SINIT`
creates `SYSTEM` via `CRUSE`, which passes literal `0`
(`.../src/TSS5.SYMB:103`). An operator must run `TRANSFER` with
`TO USER` = `FROM USER` = `SYSTEM` to mint quota before the file system is
usable — that path skips the debit leg (`.../src/TSS5.SYMB:1589`). Verified.

**5. `LOGOUT` root cause.** Not investigated. Handler is `QUIT`,
`/mnt/e/Dev/Ronny/TSS/src/TSS4.SYMB:1065-1120`. The logout accounting output is
also visibly wrong (negative seconds), pointing at `UACCT` (`:724`).

**6. Does `TDUMP` actually run under emulated TSS?** It assembles with zero
diagnostics; never executed.

**P1 - `MEMORY` hang / swapper. DONE 2026-07-27.** Root cause was a `mac-c`
code-generation bug, not a TSS bug: addressing mode 6 `,I ,X` was encoded
X-relative instead of P-relative, corrupting nine backward references in the
swapper. See section 5 item 1 for the full account. Fixed, tested, and
verified against a running machine.

*Method note worth keeping:* what found it was not DAP at all. It was a
mechanical sweep of the `mac-as -L` listing for a property that needs no
knowledge of MAC semantics — **a P-relative instruction assembled at two
different addresses must encode two different displacements.** `LDA I J2,X`
emitted the identical word `047324` at `006732` and `006746`, which is
arithmetically impossible. Invariant sweeps over the whole listing beat
single-point measurement; the same sweep also confirmed the `,B` path is
sound (`TREG` encodes `-4` at all 728 of its sites).

**P2 - `LOGOUT` leaves the terminal dead.** *Try pressing ESC.* Ronny notes
that waking a dead terminal with ESC is the normal convention under SINTRAN,
so this may not be a defect at all - the probe sent only CR. **Re-test before
treating D2 as a bug**, and if ESC revives it, correct
`docs/TSS-COMMAND-VALIDATION.md` D2 and the test methodology note that says
to use a fresh boot per session.
